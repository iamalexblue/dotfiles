# Alex 博客写作风格

为 iamalex.blue（Blue_Wonderland，astro-theme-typography 主题）写博客。仓库：`blue_wonderland`，文章在 `src/content/posts/*.md`。

一句话概括：**真诚的第一人称记录，像跟朋友聊天那样把折腾过的事讲清楚。** 技术文可以有结构，但语感永远要是"一个真实的人在说话"，不是 AI 生成的工整文章。

## 语感基准：以早期文章为准

博客早期文章（《又见白夜行》《近期小感》《谈谈腾讯》《失语者》《关于毕业、工作和未来》）是语感最好的参照——它们几乎没被 AI 打磨过，特征是：

1. **自然叙述流**。段落跟着思绪走，不强行切成 AI 式短句。一段可以很长，讲完一层意思再换段，像脑子里真在回忆。
2. **口语自然**。会写"说实话""反观""我其实蛮""有点惋惜""我一直觉得""说不上来为什么"。是聊天的语气，不是报告的语气。
3. **敢有主观判断和情绪**。喜欢就是喜欢，烦就是烦，可以自嘲（"愚钝如我"），可以直说"这东西真难用"。不需要假装客观中立。
4. **细节多于总结**。真实路径、真实版本号、真实操作过程、真实的心情变化。宁可写"我在这卡了一个小时"也不要"遇到了一些挑战"。
5. **不端着、不说教、不强行升华**。结尾往往是真实感受或一个平实的落点（"希望能给你一些参考"），不是拔高到人生哲理。
6. **句式长短交错但自然**。不为"节奏感"刻意碎句，不为"高级感"堆长句，写出来顺口就行。
7. **少用 AI 高频词**：本质上、意味着、值得一提、赋能、闭环、抓手、综上所述、值得注意的是。出现即删，换成大白话。

> 近期技术文（Homelab/CasaOS/MLX）是**结构**参照（有 ## 标题、表格、代码块），早期文章是**语感**参照。两者结合：技术内容 + 人话叙述。

## frontmatter 完整模板（写文章直接套用）

新建文章时按下面的模板生成 frontmatter，字段顺序与博客 Front Matter 插件（frontmatter.json "Touch a new post"）一致：

```yaml
---
title: 文章标题
pubDate: YYYY-MM-DD
categories:
    - tech
    # - tools
    # - homelab
description: 一句话概括全文（列表页/SEO 用，别写太长）
lastmod: YYYY-MM-DDTHH:MM:SS.000Z
draft: true   # 仅预览/未定稿时保留；确认发布后删掉这一行
---
```

字段规则：

- `title`：必填。与正文 H1 一致（正文不写 `#` 标题，主题会用 title 渲染）。
- `pubDate`：必填。`YYYY-MM-DD`（发布当天日期，无需时间部分）。
- `categories`：必填。YAML 数组，4 空格缩进，每行 `- 词`。用「frontmatter categories 词表」中的既有词，别发明新分类。排序参考同主题文章（tech 文常见 `tech` 打头）。
- `description`：可选但建议写。一句话概括，列表卡片和 SEO 会显示。别把正文摘要整段粘进来。
- `lastmod`：可选。改稿后更新时间，格式 `YYYY-MM-DDTHH:MM:SS.000Z`（带毫秒和 Z）。新建当天可省略，或用与 pubDate 相同的日期。
- `draft`：可选。`true` 时 dev 模式可见、生产构建自动过滤。用户预览确认前保留，发布时删除。
- 其他可选字段（schema 支持，按需）：`modDate`（主题排序/显示"更新于"用的实际字段）、`banner`（配图）、`author`、`pin`、`source` 等。注意：主题 PostMeta 读的是 `modDate` 而非 `lastmod`，若想让页面显示"更新于 xx"需用 `modDate`；`lastmod` 只是仓库内约定俗成的记录字段。
## 硬性排版规则（必须遵守）

1. **禁用一级标题 `#`**。正文标题从 `##` 开始。H1 由主题用 frontmatter title 渲染，正文再写 `#` 会重复且与首页博客名同字号。
2. **标题层级只用 `##`/`###`**。散文可以整篇不用小标题（像《近期小感》），tech 文才用 `##` 分节。
3. **正文开头**：frontmatter 后 tech 文常跟 `> 一句话引言` 再 `---`；散文直接进正文也行。
4. **引用块 `>`**：关键提示、结论强调、引用外部内容。
5. **表格**：对比型内容（路径对比、参数对比、验证结果）用表格，前有引导句。散文不用表格。
6. **代码**：命令/路径/文件名行内反引号；多行命令用围栏代码块并标语言。`#` 做行内注释。
7. **强调克制**：关键词可加粗，但不要大段加粗、不要满屏 emoji。✅/❌ 可用于验证结果。
8. **列表**：少条目用 `-`，有步骤用 `1.`。列表项别写成长段。
9. **中英混排加空格**：`Windows 与 Linux`、`Plasma 6.7.4`，行内代码除外。
10. **引号**：中文叙述用「」或全角引号均可，前后统一。
11. **结尾**：给小结或收尾，回扣主题。可加「参考」小节（`- [标题](url)`）。

## frontmatter categories 词表

用既有词汇：`tech`、`tools`、`thoughts`、`life`、`homelab`、`devops`、`networking`、`monitoring`、`ai`、`gaming`、`productivity`、`open-source`、`social-media`、`journal`、`film`、`anime`、`podcast`、`ramblings`。tech 长文典型组合：`tech` + `tools`/`homelab`/`devops` + 领域词。

## 结构模板（tech 折腾记，参考 Homelab/CasaOS/MLX）

1. **起因/背景**：具体问题或动机开场，真实场景，不空谈。
2. **正文分节**：现象 → 根因 → 方案 → 执行 → 踩坑 → 验证。小节标题朴素（`### 影响面盘点`、`### 三个坑`、`## 起因：xxx`）。
3. **踩坑写法**：问题 → 排查 → 真相，保留排查的思维路径（"我先怀疑是 A，测了不是，才想到 B"），比直接丢结论更像人。
4. **验证**：给可观测证据（命令输出、测试表、状态码）。
5. **小结**：列沉淀要点，可给延伸建议。

## 排版禁区（AI 味清单）

- 禁「综上所述」「值得注意的是」「不难发现」「首先…其次…最后」「让我们来看看」「在当今…时代」。
- 不写教科书式开头，从具体事件切入。
- 标题不用营销词（震惊/必看/最全），保持朴素（折腾记/手记/踩坑记录）。
- 不大量用列表堆结论，能叙述就叙述。
- 不编造没做过的实验；推断如实标"猜测/可能"。
- 不用 AI 腔排比（三连对仗句），真实口语里没人那样说话。

## 发布流程要点

- 文件名 = 标题（可含空格和中文标点）。
- 文章放 `src/content/posts/`，frontmatter 加 `draft: true` 可 dev 预览、生产自动过滤；用户确认后移除 draft。
- commit 遵循仓库惯例：`feat: 新增博客《标题》`。
- 推 `origin/main`（GitHub，Cloudflare Pages 自动部署）。
- 修改已有文章：`feat: 更新…` / `feat: 文章补充…链接`。
